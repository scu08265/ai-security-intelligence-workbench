## 4. 失败原因与降级策略

### arxiv

- 失败原因：当前网络出口访问 arXiv API 返回 HTTP 406。
- 降级策略：保留真实失败记录，使用 OpenAlex 作为论文元数据与摘要备用源。
- 历史数据：历史快照与已入库论文仍可检索；不伪造 arXiv 新数据。
- 人工动作：更换可访问 arXiv API 的网络出口后重新运行。

### openalex

- 失败原因：OpenAlex 限流、超时或响应格式变化。
- 降级策略：保留上次成功快照和已入库论文；下一计划周期重试。
- 历史数据：历史论文元数据可继续查询，但不能宣称本周期已更新。
- 人工动作：检查 OpenAlex 服务状态和查询语法。

### osv

- 失败原因：批量查询、详情请求超时或单次详情预算耗尽。
- 降级策略：只把本轮成功解析的记录标记为成功，预算未处理项标记为部分成功。
- 历史数据：历史 OSV 事件可继续使用；缺口保留并进入下一轮。
- 人工动作：提高详情预算或增加下一轮排空任务。

### msrc

- 失败原因：微软 CVRF 索引或月度文档不可用、结构变化或超时。
- 降级策略：保留最近成功的厂商公告和快照，本轮明确标记失败或部分成功。
- 历史数据：历史厂商公告仍可用；新月份更新不能视为已完成。
- 人工动作：核对 MSRC API 和 CVRF 字段结构。

### ghsa

- 失败原因：未配置 GITHUB_TOKEN 或 GitHub API 限流。
- 降级策略：未配置令牌时主动跳过，不使用空结果冒充成功。
- 历史数据：已保存的 GHSA 历史事件仍可检索。
- 人工动作：在 .env 中配置具有只读权限的 GITHUB_TOKEN。

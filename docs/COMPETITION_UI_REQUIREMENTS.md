# 赛题导向的 UI 取舍与验收清单

## 1. 使用范围

本清单依据赛题 PDF《智能体驱动的 AI 安全知识情报系统设计与实现》的三大核心能力与评分标准整理，用于约束 Codex 式 Agent 工作台的界面取舍、演示路径和验收口径。

赛题要求与 UI 的关系是：界面必须让评委看见能力、过程、结果和证据，但不能用界面目标值冒充系统实测值。产品仍围绕 AI 安全知识情报展开，Codex 式 UI 只负责把输入、编排、工具和知识的关系讲清楚。

## 2. 首页必须回答的八个问题

评委进入系统后，应在一次连贯任务中回答：

1. 系统持续监测哪些类型的来源，哪些来源本次成功、失败或尚未产生数据？
2. 一条情报从发布到首次发现用了多久，落在哪个 `≤24h / ≤12h / ≤6h` 档位？
3. 系统围绕哪些富化维度补齐信息，哪些维度仍缺证据？
4. 用户能否围绕多个文档连续追问，并看到每条回答使用了什么证据？
5. 富化准确率与召回率如何定义，当前是否真实执行过评测？
6. 问答准确率与响应时间如何定义，是否达到赛题的 `准确率≥75% 且响应≤5s` 合格线？
7. 哪些 Agent 角色作了决策，调用了哪些工具，为什么继续、停止或转人工？
8. 自动化遇到限流、超时、缺少 Token 或数据异常时如何处理，是否存在有证据的自愈闭环？

上述八项应在“工作台任务结果 + 系统详情/质量”两层内完成，不要求用户在大量独立窗口间跳转。

## 3. 必须展示的赛题能力

### 3.1 多源监测

工作台和系统详情必须展示：

- 来源按类型分组，至少区分漏洞数据库、安全社区、厂商公告、安全博客/技术内容、学术论文、标准与政策等系统实际登记类型。
- 每个来源的接入方式、启用状态、最近运行、最近成功、最近错误和有效事件数。
- 一次采集的抓取、过滤、保留、新增、更新、耗时、快照和失败原因。
- 增量采集、归一与去重是否实际执行；没有运行证据时不标“已实现”。
- “登记来源数”和“产生有效数据的来源数”分开统计。

UI 不使用“覆盖广泛”“实时监测”等空泛徽章。来源类别数由接口中的实际数据计算；是否实时必须有持续运行或调度证据。

验收动作：评委选择一个或多个已登记来源发起采集，界面显示真实步骤、逐来源结果、快照或错误，并可从新增事件回到来源记录。

### 3.2 监测时效性：`≤24h / ≤12h / ≤6h`

必须提供“发布到发现延迟”视图，并明确：

- 单条事件延迟 = 系统首次发现时间 - 来源发布时间。
- 只有两个时间都存在且可解析时才进入统计。
- 展示可计算样本数、未知样本数，以及 `≤24h`、`≤12h`、`≤6h` 的数量与比例。
- 单条事件展示来源发布时间、首次发现时间和延迟。
- 赛题分档标注为：`≤24h 合格目标`、`≤12h 良好目标`、`≤6h 优秀目标`。

赛题阈值是评价目标，不是默认成绩。系统当前只有 `≤24h` 观测时，不得由 UI 推算或宣称已经达到 `≤12h`、`≤6h`。

验收动作：打开一个具有有效发布时间和发现时间的事件，核对单条延迟；再核对聚合样本分母和未知数量。

### 3.3 富化维度

事件详情必须以维度清单或覆盖图展示至少这些赛题相关维度：

- 关联技术论文与分析文章。
- 受影响组件、版本与互联网/受管资产。
- POC 状态与来源，仅记录，不执行。
- CVSS 评分、向量与来源。
- 影响评估与资产关联判断。
- 修复版本或缓解措施。
- 官方来源与证据完整性。
- 漏洞关系、攻击链或相关事件；只有证据支持时展示。

每个维度显示“有证据 / 缺失 / 待确认 / 不适用”，并附证据 ID 或缺口说明。维度数量从事件富化结果计算，不把空字段算作已完成。

验收动作：选择一个事件运行富化，界面显示富化前后差异、工具调用、增加的证据、仍未解决的缺口和停止原因。

### 3.4 富化准确率与召回率

“运行与质量”必须同时给出准确率和召回率，避免只显示一个通过率：

- 准确率：系统给出的富化关系中，经金标准验证为正确的比例。
- 召回率：金标准要求的富化关系中，被系统成功找回的比例。
- 同时展示样本集、样本量、执行时间、金标准来源、合成样本标记和局限性。
- 展示赛题决赛分档：`准确率≥80% 且召回率≥70%` 为合格目标，`均≥90%` 为良好目标，`均≥95%` 为优秀目标。
- 初赛“准确率≥70/85/95%”可放在评分说明中，不与决赛口径混为同一指标卡。

若现有评测没有分别测量富化准确率和召回率，界面必须显示“未评测”，不能用事件完整度、用例通过率或检索召回率替代。

验收动作：运行一套有版本和来源记录的固定评测集，UI 展示混淆/命中明细，能够从错误样本回到系统产出与金标准。

### 3.5 跨文档与多轮问答

问答区必须让用户和评委看出“检索了哪些文档、如何沿用上下文”：

- 每轮问题和回答保持在同一任务线程中。
- 后续问题可引用前一轮的事件、资产和限定条件，并在界面显示当前会话上下文。
- 回答展示相关事件、检索命中文档、引用证据和每个事实声明对应的证据 ID。
- 跨文档回答至少使用两个独立知识对象或来源时，才标记“跨文档”；只命中一个对象时如实显示单文档。
- 多跳推理要展示可复核的关系链和条件，不展示模型隐藏思维过程。
- 证据不足时拒答，并说明缺失文档或字段。

验收动作：先问某漏洞影响范围，再追问“其中公开暴露的资产如何修复”，随后询问“该判断还缺什么证据”；线程应沿用上下文，且每轮引用可核对。

### 3.6 问答准确率与 `≤5s`

质量页面必须展示：

- 问答准确率、题目数量、题型分布和逐题结果。
- 首字响应时间与完整响应时间，二者名称不可混用。
- 响应时间的样本数、中位数、P95 和失败/超时数量。
- 赛题决赛合格目标：`准确率≥75% 且响应≤5s`。
- 赛题良好目标：`准确率≥90% 且支持多跳推理`。
- 赛题优秀目标：`准确率≥95% 且推理链可解释`。

若赛题原文没有明确“≤5s”指首字还是完整回答，系统应选定并固定一种主口径，推荐使用完整响应时间；首字时间作为流式体验辅助指标。UI 必须注明口径。

未执行真实计时评测时显示“未评测”；单次演示耗时不能代表整体 `≤5s` 达标。

验收动作：运行固定问答评测，查看准确率与逐题耗时；失败、拒答和超时样本进入分母并可展开检查。

### 3.7 Agent 角色、编排与工具调用

任务工作区必须展示：

- Agent 角色及职责，例如规划、检索/查证、证据审核、影响研判和回答组织。
- 一次任务的计划、当前步骤、角色交接、工具选择、调用预算、停止条件和人工确认点。
- 工具名称、调用原因、输入摘要、返回摘要、真实耗时、错误和证据产物。
- 角色是同一编排进程内的职责分工时，要如实说明，不能包装成多个独立自主 Agent。
- 自主决策只体现在有记录的工具选择、补证策略、停止/转人工判断中。

验收动作：发起一个需要补证的研判任务，从计划到工具调用再到结果完整展开；评委可以解释“谁决定调用什么、依据是什么、为什么停止”。

### 3.8 自动化、异常处理与自愈

UI 必须区分三个成熟度：

| 层级 | 可见证据 |
| --- | --- |
| 自动化 | 采集、归一、富化、研判、问答按流程连续执行，有运行 ID 和状态 |
| 异常处理 | 超时、限流、缺少 Token、格式异常、部分成功有明确分支和错误记录 |
| 自愈 | 系统自动重试、切换备用来源、降级或恢复后复跑，并有前后状态与成功证据 |

仅有重试按钮、错误提示或人工再次运行，不得标记为“自愈”。若数据库只记录流程运行而不能证明由调度器自动触发，应显示“触发方式未知”。

自愈轨迹至少显示：异常类型、检测时间、系统动作、重试/降级次数、最终状态、证据产物和是否需要人工处理。自动操作必须受工具白名单、调用预算和授权范围限制。

验收动作：用可控失败场景验证异常被识别并留下记录；只有系统自动执行恢复动作并获得结果，才通过自愈验收。

## 4. UI 窗口取舍

### 4.1 保留的四个顶层入口

1. **工作台**：任务输入、对话、计划、步骤、工具调用、交付结果。
2. **知识库**：事件、文档、证据、关系图、时间线和资产影响矩阵。
3. **资产**：受管资产、授权、版本、暴露面和配置条件。
4. **系统详情**：来源与采集、Agent 与工具、运行与质量、自动化与自愈、状态说明。

### 4.2 删除或合并的冗余窗口

| 当前窗口/能力 | 处理方式 | 合并后的承载位置 |
| --- | --- | --- |
| 风险总览 | 合并，不再作为独立顶层页 | 工作台空闲态的真实状态摘要和任务模板 |
| 风险处理过程/看它怎么工作 | 合并 | 当前任务的编排步骤流 |
| 证据问答 | 合并 | 工作台固定输入层与同一任务线程 |
| 处置清单 | 合并 | 任务最终交付 + 知识库资产影响矩阵 |
| 风险与证据 | 合并 | 知识库事件详情、证据链与关系图 |
| 知识分类/文档列表 | 合并 | 知识库的文档、图谱、时间线切换视图 |
| Agent 架构说明 | 合并 | 系统详情 + 每次任务的就地角色/工具轨迹 |
| 来源与采集 | 保留为系统详情子页 | 系统详情“来源与采集” |
| 运行日志与评测 | 合并 | 系统详情“运行与质量” |
| 状态说明/图例 | 合并 | 系统详情末级帮助；关键状态仍就地解释 |

以下重复表现应删除：

- 同一运行在“流程直播”“运行日志”“Agent 轨迹”分别出现三套时间线，统一为一套任务步骤流。
- 首页、处置页和事件页重复展示同一风险计数，首页保留摘要，其余页面只显示当前筛选范围。
- AI 参与说明在多个页面大段重复，改成顶部模式标识、步骤就地标签和系统详情完整说明。
- 工具目录与来源表重复列出同一外部端点，工具目录讲“能做什么”，来源表讲“从哪里取得数据”，通过 ID 关联。
- 文档列表、事件列表和搜索结果各自弹出不同详情窗，统一为右侧详情抽屉。
- 单独的“数据可视化大屏”不作为顶层入口；图谱、时间线和矩阵放回知识任务上下文。

### 4.3 不应删除的证据入口

窗口可以合并，但以下信息不能因简化而隐藏：逐来源结果、原始链接或快照、证据 ID、Agent 步骤、工具错误、评测样本与局限、自愈轨迹、未知值。

## 5. 实际值、未知和规划的展示规则

所有赛题指标和能力使用三态口径：

| 状态 | 使用条件 | UI 表现 | 禁止做法 |
| --- | --- | --- | --- |
| 实测 | 已有可复核运行、样本、时间戳或评测记录 | 显示数值、分子/分母、窗口、运行时间、证据入口 | 用单次演示替代整体指标；隐藏失败样本 |
| 未知/未评测 | 缺少必要字段、样本或尚未运行 | 显示“未知”“未评测”“无可计算样本”，并说明缺什么 | 显示 0、100%、空白或“已达标” |
| 规划 | 设计目标或尚未落地能力 | 显示“规划”，可附目标和验收条件 | 使用完成态颜色、勾选或当前能力语气 |

赛题阈值统一标“赛题目标”，例如：

- `当前实测：未知｜赛题合格目标：≤24h`
- `当前实测：未评测｜决赛合格目标：准确率≥80%、召回率≥70%`
- `当前实测：<接口返回的完整响应时间>（n=<有效样本数>）｜决赛合格目标：≤5s`
- `自愈：规划｜通过条件：自动检测异常并完成有记录的恢复动作`

只有满足全部条件时才显示“达到某档”：指标定义一致、样本非空、评测真实执行、分母和失败项可见、证据可回溯。达到低档但未达到高档时，只高亮实际达到的最高档。

## 6. 演示主线

现场演示使用一条任务贯穿赛题要求：

> 监测最新 AI 安全风险，补齐影响与修复证据，关联我的资产，并回答处置问题。

推荐演示顺序：

1. 在工作台输入任务，确认来源、时间窗口、资产和工具预算。
2. 展开编排计划，看到 Agent 角色选择已登记工具。
3. 展示多源采集的成功、部分成功或失败，以及去重结果。
4. 打开某事件的发布—发现时间线，展示可计算延迟和赛题分档。
5. 展开富化维度，展示新增证据、缺口、关联资产和来源冲突。
6. 连续提出基础问题、上下文追问和跨文档问题，核对引用。
7. 查看最终处置清单与资产影响矩阵。
8. 打开运行与质量，展示已真实执行的富化准确率/召回率、问答准确率/响应时间；未评测项如实保留。
9. 打开异常或自愈轨迹，说明系统已实现到哪个成熟度。

## 7. 发布前验收清单

### 赛题可见性

- [ ] 多源类别、逐来源状态和采集结果可见。
- [ ] 增量、去重和自动化状态有运行证据。
- [ ] 富化维度、证据 ID、缺口和停止原因可见。
- [ ] 多轮上下文与跨文档引用可核对。
- [ ] 发布到发现延迟按 `≤24h / ≤12h / ≤6h` 展示样本与分档。
- [ ] 富化准确率和召回率同时展示，或明确标记未评测。
- [ ] 问答准确率、完整响应时间和 `≤5s` 目标同时展示，或明确标记未评测。
- [ ] Agent 角色、计划、工具调用、预算和停止条件可见。
- [ ] 自动化、异常处理、自愈三种成熟度没有混用。

### 真实性

- [ ] 所有数字来自接口或可复核评测产物。
- [ ] 目标阈值带“赛题目标”标签。
- [ ] 未知不是 0，未评测不显示分数。
- [ ] 演示资产和合成样本有显著标记。
- [ ] 失败、跳过、超时和部分成功进入结果与指标分母。
- [ ] 跨文档、多跳、自主决策、自愈等标签都有运行证据。

### 界面收敛

- [ ] 顶层入口收敛为工作台、知识库、资产、系统详情。
- [ ] 对话、流程直播、Agent 轨迹使用同一任务工作区。
- [ ] 风险、证据、文档、关系使用同一详情抽屉。
- [ ] 质量指标集中在一个页面，不在多个窗口出现不同口径。
- [ ] 颜色之外有文字状态，窄屏和键盘访问可用。

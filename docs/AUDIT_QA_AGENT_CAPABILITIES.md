# 严格审计：深度问答与 Agent 架构声明

## 1. 审计结论

对照赛题 PDF、当前实现、自动化测试、标注题集和最近一次持久化评测，结论如下：

| 能力 | 实现证据 | 测试/评测证据 | 审计判断 | 当前允许表述 |
| --- | --- | --- | --- | --- |
| 深度语义理解 | 本地 BM25、字符重叠、少量中英词扩展、标识符与组件匹配 | 有改写查询和单复数选择的单元测试；标注题集只有 4 题 | 有轻量混合检索能力，未完成“深度语义理解”专项测量 | “支持本地混合检索与有限查询改写” |
| 多轮问答 | 最近 4 条历史中按事件 ID、组件和代词恢复上下文 | 2 个直接单测；标注集 1 个合成代词追问 | 基础指代追问已测，真实多轮任务、条件继承、纠错未测 | “支持基于历史事件标识的基础追问” |
| 跨文档问答 | 一次可选择最多 5 个事件并逐条组织回答 | 单测验证同一组件下返回两个事件；未验证综合结论 | 多事件召回已测，跨文档综合推理未测 | “可检索并并列呈现多个事件” |
| 多跳推理 | 能输出已有 `relationships`，无来源关系时拒答 | 只测缺关系时拒答；没有多跳金标准 | 未实现或未证明动态多跳路径搜索与结论组合 | 不可声称“支持多跳推理” |
| 个性化推荐 | 根据资产版本、暴露面、关键性和条件生成确定性研判/优先级 | 有资产影响和修复证据绑定测试 | 有资产上下文研判，没有用户画像、反馈偏好或推荐效果评测 | “提供基于受管资产事实的处置建议”，不可称个性化推荐 |
| 推理可解释 | 回答含 claims、evidence_ids、trace、limitations；研判含 reasons | 有证据绑定、停止原因、拒答与流式一致性测试 | 结论依据和执行轨迹可解释；没有模型思维链，也不应展示隐藏思维链 | “结论与工具轨迹可追溯、证据可核验” |
| Agent 自主编排 | 状态机、职责角色、缺口到工具规划、两轮/三次预算、停止条件 | 规划、工具去重、预算、失败、状态迁移测试 | 是有界规则编排；不是多个独立 Agent 协作，也没有开放式自主规划 | “有界 Agent 编排与工具调度” |
| Agent 架构创新 | 证据缺口驱动的只读工具调度、保守停止、全链路证据留痕 | 有回归测试，未做对照实验或消融实验 | 工程设计有特色，但“创新且效果显著”没有量化证明 | 可描述设计亮点，不可宣称创新效果已验证 |

## 2. 赛题要求基线

赛题对问答能力的分级为：

- 初赛合格：基础关键词检索问答。
- 初赛良好：语义理解与多轮对话。
- 初赛优秀：跨文档推理与深度分析。
- 决赛合格：语义问答。
- 决赛良好：多轮对话与推理。
- 决赛优秀：深度推理与个性化推荐。

决赛问答质量还要求：准确率达到相应阈值、响应速度达标、多跳推理或可解释推理链。Agent 评价关注自主决策、多 Agent 协作、任务编排和工具调用；“多 Agent 协作编排”和“Agent 架构创新且效果显著”属于更高档声明。

因此，页面存在多轮历史、多个检索结果或执行轨迹，并不自动等于已经达到赛题的高级档。

## 3. 深度语义理解审计

### 已有证据

- `app/intelligence.py::hybrid_search_events` 使用 BM25 风格词项得分、字符重叠代理、事件标识符精确匹配和组件加分。
- `_terms` 只有一个小型、可审计的中英安全词汇扩展表。代码注释明确说明它不是嵌入模型。
- `tests/test_intelligence.py::test_hybrid_search_handles_paraphrase_and_cross_document_results` 验证英文改写查询可召回两个合成事件。
- `test_singular_component_question_ranks_one_but_plural_keeps_many` 验证单数/复数意图下的候选选择。
- 标注评测包含一个真实 vLLM 视频漏洞检索题，但没有同义改写、否定、比较、时间限定、复合约束等题组。

### 缺口

- 没有语义检索基线对照，例如关键词、BM25、当前混合检索、向量/重排方案的同集比较。
- 没有困难负样本、近义事件、跨语言改写、长查询或歧义消解的分层指标。
- 当前模型辅助路径只从允许列表返回事件 ID，并未生成或验证深度语义推理。
- 最近评测的检索精确率/召回率来自极小题集，`TP=3、FP=0、FN=0`，不能外推为生产语义能力。

### 不能声称

- “具备深度语义理解”。
- “语义检索准确率 100%”。
- “经过大规模、多领域或第三方验证”。

### 改造与评测方案

建立至少 100 条冻结查询，覆盖精确编号、同义改写、中英混合、否定、比较、多约束、歧义和无答案；每题由独立标注者给出相关事件集合。报告 Recall@k、MRR、nDCG、困难负样本准确率，并对关键词、当前混合检索和候选重排做消融对照。真实案例与合成题必须分开统计。

## 4. 多轮问答审计

### 已有证据

- `_select_events` 在当前问题含“它、该、这个、this、it、that”等指代词时，从最近 4 条历史中寻找事件 ID 或组件。
- `test_follow_up_uses_history_and_remote_failure_degrades` 验证“它影响资产吗”。
- `test_multiturn_pronoun_can_request_fix_version` 验证“它的修复版本是什么”。
- `evaluation/gold_cases.json` 有 1 条合成多轮代词用例，历史直接包含合成 CVE 编号。

### 缺口

- 历史只用于恢复事件，不维护资产选择、时间范围、前一轮约束、用户纠正或多个候选之间的指代。
- 没有真实来源多轮金标准；没有 3 轮以上对话。
- 没有测试话题切换、回指错误、用户撤销条件、多个事件并行讨论和历史污染。
- 标注集的多轮题把事件 ID 直接写在上一轮助手文本中，难度很低。

### 不能声称

- “支持复杂多轮推理”。
- “能稳定理解长对话上下文”。
- “多轮问答准确率达到比赛高档要求”。

### 改造与评测方案

建立 30 组真实案例对话，每组 3-6 轮，覆盖事件回指、资产回指、条件继承、条件修改、对比追问、话题切换和拒答。逐轮标注目标事件、资产、约束、期望证据和答案要点；报告逐轮正确率、整段对话全对率、上下文继承错误率和无关历史鲁棒性。

## 5. 跨文档与多跳推理审计

### 已有证据

- 查询可返回最多 5 个事件，回答循环逐条输出事件摘要和来源。
- 一个单元测试验证同一组件的两个事件都出现在 `related_event_ids`。
- 当事件已有带 `evidence_ids` 的关系时，攻击链回答可以把关系格式化为“主体 → 关系 → 客体”。
- 缺少有来源关系时，系统明确拒绝补写攻击链；相关测试已覆盖。

### 缺口

- 当前“跨文档”测试只证明多事件召回，不证明两个文档的事实被组合成一个新结论。
- 两个测试事件还共享同一个夹具证据 ID，不能证明独立来源交叉验证。
- 没有文档 A → 实体 B → 文档 C 的路径搜索、关系约束、冲突处理或答案综合。
- 没有多跳题集、路径金标准、跳数分层、路径证据完整率或最终答案评分。
- 攻击链输出读取预存关系，属于证据呈现，不等同于在线多跳推理。

### 不能声称

- “已实现跨文档关联推理”。
- “支持多跳推理”。
- “能够自动发现完整攻击链”。

### 改造与评测方案

构建独立来源的关系数据和三类题：两文档事实合并、两跳关系链、三跳关系链。每题标注所需文档、实体、边、路径和答案；系统输出结构化 `reasoning_path`，其中每条边绑定证据 ID。报告文档召回率、路径精确率/召回率、最终答案准确率、证据完整率，并按 1/2/3 跳分别统计。冲突来源应有专门用例，答案必须保留冲突而非静默合并。

## 6. 个性化推荐审计

### 已有证据

- `assess_asset` 使用资产组件、版本、暴露面、业务重要性、授权和关键配置形成四档结论与优先级。
- 修复回答能把已记录的修复版本绑定到证据，并针对匹配资产生成建议。
- 相关测试覆盖受影响判断和修复证据绑定。

### 缺口

- 不存在用户画像、组织策略、维护窗口、风险偏好、角色权限或反馈学习。
- 没有候选动作排序的推荐基线，也没有采纳率、命中率、人工评价或 A/B 对照。
- 当前输出是资产上下文下的规则化处置建议，不能等同于赛题语境中的个性化推荐。

### 不能声称

- “支持个性化推荐”。
- “会根据用户偏好学习”。
- “推荐效果已验证”。

### 改造与评测方案

先定义可审计的组织策略输入，例如业务关键性、维护窗口、可接受停机、组件负责人和禁止动作；以规则方式生成候选处置并解释每个排序因素。建立专家标注的资产—事件—动作排序集，报告 Top-1/Top-3 命中率、NDCG、不可执行建议率和专家一致性。没有真实用户反馈前，称“策略感知建议”比“个性化推荐”更准确。

## 7. 推理可解释审计

### 已有证据

- 回答返回 `claims[].evidence_ids`、引用、执行 `trace`、局限和停止原因。
- 资产研判返回状态、理由和证据 ID。
- 富化返回维度、缺口和检查轨迹。
- 流式测试验证最终文本与引擎答案一致，模型输出与证据绑定文本分开标记。

### 缺口

- 当前 trace 主要描述执行步骤，不是对每个复杂结论的完整逻辑证明。
- 只有少量引用准确率题；最近评测的引用指标分母为 1。
- 没有人工评测解释的忠实性、充分性、可读性和可复现性。
- 没有验证移除某条证据后结论是否相应改变，因此无法证明解释忠实于实际决策。

### 不能声称

- “完整展示模型推理链”或“公开思维链”。
- “推理解释准确率 100%”。
- “所有回答均已完成解释忠实性验证”。

### 改造与评测方案

输出面向审计的结构化理由图，而不是隐藏思维过程：结论节点、规则/关系边、事实节点和证据 ID。对每条答案测引用支持率、证据充分率、矛盾率；用证据删除和替换实验测解释忠实性。至少两名安全专家独立评分解释是否足以复核，并报告一致性。

## 8. Agent 架构创新性审计

### 已有架构价值

- 持久化状态机记录 `discovered → normalized → pending_enrichment/review → published/invalidated`。
- 富化先审计证据缺口，再由 planner 把缺口映射到 NVD、MITRE、OSV、KEV 等只读工具。
- 调度器最多 2 轮、3 次工具调用，避免重复工具；记录每次返回、失败和停止原因。
- 未取得新证据时停止，不把“查无结果”解释为安全。
- 角色、工具、预算、状态和证据可以审计，模型只允许从候选 ID 中选择并能降级到本地路径。
- 相关测试覆盖缺口规划、工具去重、预算上限、失败记录、状态迁移、撤回失效和未知保守处理。

### 创新性缺口

- planner 是“缺口标签包含关键字 → 固定工具”的确定性映射，没有任务分解、候选计划比较或基于执行结果的重规划。
- collector、normalizer、planner、retriever、auditor 等是单进程职责标签，不是可独立通信、并行协作和互相校验的多个 Agent。
- 不存在角色间消息协议、共享任务黑板、冲突仲裁、并行执行或独立审核模型。
- 没有 Agent 与非 Agent 基线对照，也没有消融“无规划、无审核、无预算”后的准确率、覆盖率、成本和耗时变化。
- 没有从历史成功/失败中学习策略，也没有完整自愈闭环。
- 最近 scorecard 只统计角色步骤和工具调用次数；次数不能证明自主决策质量或架构创新效果。

### 当前可守住的声明

> 系统实现了证据缺口驱动的有界 Agent 编排：状态机负责阶段推进，规划职责根据缺口选择白名单只读工具，调度器在轮次和调用预算内执行，证据审核职责决定发布、待复核或停止。所有角色均为同一进程内的可审计职责分工。

### 不能声称

- “多 Agent 自主协作已经实现”。
- “Agent 会自主生成任意计划并动态调用任意工具”。
- “Agent 架构创新且效果显著”。
- “具有学习能力或完整自愈能力”。

### 改造与评测方案

1. 把任务计划表示为结构化 DAG，节点包含前置条件、工具候选、成功判据、预算和人工确认点。
2. 让 planner 根据目标与缺口生成多个受白名单约束的候选计划，由 auditor 检查权限、证据需求和预算后选择。
3. 工具返回后根据“缺口是否减少、是否冲突、是否失败”重规划，而不是只按固定顺序继续。
4. 若确需宣称多 Agent，至少实现独立规划、检索和审核执行单元，使用明确消息契约并记录交接；审核单元应能否决无证据结论。
5. 建立对照实验：固定流水线、单 Agent 有界编排、多角色审核编排三组使用同一任务集；比较任务成功率、证据完整率、错误结论率、工具调用数、耗时和成本。
6. 做消融实验：移除 planner、auditor、预算或停止策略，量化每项设计的实际贡献。
7. 自愈另设故障注入实验，验证超时、限流、无 Token、格式变化和来源失效后的重试、降级和恢复。

## 9. 当前评测数据应该如何解释

最近一次持久化评测记录显示：本地回归 30/30 通过；标注问答集的 retrieval precision、retrieval recall、answer accuracy、citation accuracy、refusal accuracy 均为 1.0；响应耗时样本 4 条。

这些数值只能解释为“当前代码在团队自建的小样本回归集上通过”。关键分母为：检索真阳性 3、回答题 3、引用题 1、拒答题 4；题集包含 2 条真实核验题与 2 条合成回归题，其中多轮题是合成。评测非盲测、非第三方标注，也未覆盖模型辅助路径。它不能证明比赛级深度问答能力，更不能证明多跳或个性化推荐。

建议 UI 把“30/30 规则回归”与“4 条问答标注集”拆开，分别展示分母和局限。禁止只显示一个醒目的“准确率 100%”。

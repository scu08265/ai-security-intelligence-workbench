## 0. 口径声明（先读这一节）

| 指标 | 定义 | 是否已计算 |
| --- | --- | --- |
| 引用命中率 | 预期 `document_key` **全部**被引用命中的比例；分母 = 带预期文档的题目数 | ✅ 机械判定 |
| 预期词命中率 | 预期答案要点**逐字**出现在答案中的比例；分母 = 带预期词的题目数 | ✅ 机械判定，**不是**语义准确率 |
| 拒答一致率 | 拒答判定与 `should_refuse` 一致的比例；分母 = 全部题目数 | ✅ 机械判定 |
| 引用可追溯 | 引用的 `chunk_id` 能否在库中取回 | ✅ 机械判定 |
| P50 / P95 / 超时 | 单题端到端耗时；超时阈值 5000 ms | ✅ 实测 |
| **语义答案准确率** | 答案是否**正确**回答 | ❌ **未计算** |

**语义答案准确率未计算的原因**：本评测集的标准答案要点由任务执行者编写，全部标记
`verification_status = pending_human_review`。按规则，无人工核验标准答案的题目不得计入
正式准确率分母。**本轮没有任何人工标注者参与，因此不发布准确率数字。**

因此本报告**不主张**赛题的任何档位（75% / 90% / 95%）已经达到。

## 3. 阶段 A：上一轮修复的复核结论

| 检查项 | 结论 |
| --- | --- |
| D-1 是否仍保留区间合法性校验 | ✅ 保留：`start < 0 or end != start + len(text)`；校验与 `Chunk.text` 都用存储原文 |
| D-2 未知专名是否会误命中 | ✅ 不会：未知专名词元 df=0 → `matched` 为空 → 被首道守卫拒绝 |
| D-4 是否只消除表面矛盾 | ✅ 不是：答案、trace、limitations 三者同步改判，且仅在"事件路径无任何证据"时触发 |
| D-4 是否会把不足证据拼成结论 | ✅ 不会：答案只由 `citations[:3]` 的逐字原文用 `- ` 拼接，`tests/test_rag_answer_grounding_edges.py` 断言答案长度 ≤ 模板 + 引用原文总量 |
| 事件路径与文档路径优先级 | ✅ 事件路径有答案时不被覆盖；文档引用也不会被清空 |
| 公开返回结构兼容性 | ✅ 字段未增未减（`test_response_structure_is_unchanged`） |

阶段 A 新增 `tests/test_rag_answer_grounding_edges.py`（**17 项**），补齐 7 个边界场景。

## 4. 本轮在 `app/rag.py` 内补修的两个缺陷（阶段 A/B 发现）

| 编号 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| N-1 | 专名 `JevOut` 永远检索不到 | `terms()` 的正则把尾随 `:` `.` `/` 吞进词元，正文标题 "JevOut:" 变成 `jevout:`，与查询 `jevout` 不相等 | 词元首尾剥离 `_.:/+-`，词内部符号保留（`cve-2026-41106`、`0.28.0` 不受影响） |
| N-2 | `kernel-level`、`multi-agent` 作为唯一匹配词时被拒 | D-2 阈值 `语料量/20 = 181` 过严（`kernel-level` df=328、`multi-agent` df=293） | 放宽到 `语料量/10 = 363`：`ai`(1301)、`model`(729)、`security`(505) 仍被拒绝 |

两处都补了回归测试（`tests/test_rag_mixed_language_query.py` 由 18 项增至 30 项）。

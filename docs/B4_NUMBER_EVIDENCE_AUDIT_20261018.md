## 6. 本轮新发现（不在"数字对错"范围内，但影响口径）

1. **10-18 的 31 题变化不是单一原因**。`ec57d09`（2026-10-17 23:56，答案改为先结论后证据）与
   B1/B2 的语料重建**同时**作用在 10-18 机器结果上；没有做单因素 A/B，因此不能把单题差异归给
   "PDF 抽取修复"。批次说明见 `docs/B4_BATCH_CONSISTENCY_20261018.md`。
2. **10-18 答案首句常是片段**：31 道变化题里 26 道首句在词/句中途截断，4 道以小写片段开头
   （如 `uestion for multi-agent LLM systems`）。这是 `ec57d09` 的选句行为，不是数据错误，
   但会增加人工判读成本；已逐题写进 `B4_HUMAN_REVIEW_20261018.csv` 的 `lead_quality_note`。
3. **术语覆盖数不能换机复算**：本机 `data/intel.sqlite` 是空库，直接构建会输出"0 条覆盖"。
   报告已改为只报种子条数并指向接口，避免把"本机没挂语料"写成产品读数。
4. **781 vs 1334**：报告第二章的"781 条运行记录"与快照 `runs = 1334` 不是同一口径，二者不能同时出现
   在同一份材料里而不加说明。已列入 UNVERIFIED。
5. **确认表答案列被截断**：`qa_final_confirmation_worksheet_20261018.csv` 的 `system_answer` 由
   `tools/build_b_qa_candidate_answers.py` 截到 600 字符，50 行里 21 行带"…"。批次本身没问题
   （refused/latency/ID 与 10-18 结果逐项一致），但人工判引用支持时需要完整正文——
   完整答案在 `B4_HUMAN_REVIEW_20261018.csv` 的 `old_answer_1012` / `new_answer_1018`，
   或 `formal_qa_results_20261018.json → records[].answer_full`。

# 完整 Agent 项目分阶段架构与验收计划

## 1. 升级目标

项目应从“带角色标签的固定安全流水线”升级为“证据约束、可恢复、可评测的 AI 安全知识 Agent”。完整形态需要同时具备：

- 用户任务与多轮上下文可持久化。
- 原始文档全文留存、可分块检索并能精确引用。
- 任务计划使用可执行 DAG 表达，并能根据工具结果重规划。
- 多角色通过明确协议交接，审核角色可以否决无证据结论。
- 所有工具遵循统一输入、输出、权限、预算和错误协议。
- 短期会话记忆与长期知识记忆分离，写入和失效可审计。
- 评测覆盖检索、富化、多轮、跨文档、多跳、引用、拒答、时延与 Agent 效果。
- 真实采集产生连续运行证据，赛题指标只显示可复核实测值。

升级过程不能牺牲当前系统已经具备的优势：固定来源白名单、原始快照、证据 ID、未知保守处理、合成数据标识和失败如实展示。

## 2. 当前基线与禁用声明

| 领域 | 当前已有能力 | 当前缺口 | 现阶段禁用声明 |
| --- | --- | --- | --- |
| 资产输入 | 已支持 CycloneDX JSON 1.3–1.7 预览、幂等导入、来源保真和批次研判；演示资产有 `is_demo` 标识 | 尚未支持 SPDX、VEX、依赖传播和真实 CMDB/SBOM 接入评测 | 不得称“已完整支持所有 SBOM/VEX”或“已接入真实企业资产” |
| 资产研判 | 按组件、版本、暴露面、关键性与条件生成四档结论 | 没有完整依赖树、传递依赖和 CPE/PURL 映射评测 | 不得称“完整供应链依赖分析” |
| 检索问答 | 本地混合检索、基础历史指代、证据绑定回答与拒答 | 没有全文分块索引、真实多轮集和跨文档综合推理 | 不得称“全文 RAG”“深度语义”“跨文档/多跳已验证” |
| 编排 | 状态机、职责角色、固定工具、轮次/预算和停止原因 | 不是通用 DAG，角色不是独立 Agent | 不得称“多 Agent 自主协作”或“开放式自主规划” |
| 工具 | 白名单来源、只读补证、快照与错误记录 | 尚无统一版本化工具协议、幂等键和通用权限声明 | 不得称“可自主调用任意工具” |
| 记忆 | 请求携带短历史；运行、事件和证据可持久化 | 没有结构化会话记忆、长期偏好和失效机制 | 不得称“长期记忆”或“自动学习” |
| 解释 | claims、证据 ID、理由、轨迹、局限和停止原因 | 没有多跳理由图和解释忠实性评测 | 不得称“完整思维链”或“推理解释已验证” |
| 评测 | 本地规则回归与 4 条 QA 标注题；合成样本有标识 | 非盲测、样本小，未覆盖高级能力 | 不得把本地满分宣传为比赛准确率 |
| 真实采集 | 登记来源采集、逐来源状态、快照、监测证据账本 | 连续 7 天与 `≤6h` 达标需要真实时间积累 | 未达到证据门前不得称“连续稳定运行”或“优秀时效” |

以下章节描述升级目标。任何未通过对应阶段验收门的能力，在产品中只能标记为“规划”或“未评测”。

## 3. 目标架构

### 3.1 分层结构

| 层 | 核心组件 | 责任 | 主要产物 |
| --- | --- | --- | --- |
| 输入与会话层 | Task API、会话线程、上下文选择器、人工确认 | 接收目标、资产范围、时间窗口、约束与反馈 | `task`、`thread`、`turn`、`context_snapshot` |
| 编排层 | DAG Planner、Scheduler、Policy Guard、Checkpoint | 分解任务、处理依赖、预算、暂停、重试、重规划 | `plan`、`node_run`、`handoff`、`checkpoint` |
| 角色层 | Planner、Retriever、Analyst、Assessor、Auditor、Writer | 按契约完成独立职责并交接结构化结果 | 角色产物、审计意见、接受/驳回记录 |
| 工具层 | Tool Registry、采集器、全文检索、关系检索、规则研判 | 执行确定性或受限外部动作 | `tool_call`、`tool_result`、错误、快照 |
| 知识与 RAG 层 | 文档库、解析/分块、索引、实体关系、引用解析 | 保存全文、块、实体、关系与版本 | `document`、`chunk`、`entity`、`relation`、`citation` |
| 记忆层 | Working Memory、Thread Memory、Knowledge Memory | 保持当前任务状态、会话摘要和经审核事实 | `memory_item`、来源、有效期、失效记录 |
| 评测与观测层 | Gold Set、Trace Store、Metrics、Scorecard | 测量质量、耗时、成本、稳定性和赛题指标 | 逐题结果、聚合指标、运行证据 |

### 3.2 核心对象契约

#### Task

```text
id, objective, thread_id, status,
scope {asset_ids, source_ids, time_window},
constraints {tool_budget, deadline, model_allowed},
plan_id, created_at, updated_at
```

状态至少包括：`draft / planned / running / waiting_human / completed / partial / failed / cancelled`。

#### Context snapshot

```text
task_id, turn_id,
selected_event_ids, selected_asset_ids, selected_document_ids,
resolved_references, inherited_constraints,
source_versions, created_at
```

每次执行固定一份上下文快照，避免知识库更新后无法复现旧答案。

#### DAG node

```text
id, plan_id, role, action,
depends_on[], input_refs[], expected_output_schema,
tool_candidates[], success_criteria,
retry_policy, budget, status
```

DAG 节点不能只保存自然语言。依赖、输出模式、成功判据和预算必须可由调度器验证。

#### Handoff

```text
from_role, to_role, task_id, node_id,
objective, input_refs[], produced_refs[],
open_questions[], confidence, limitations,
accepted, rejection_reason, created_at
```

角色交接传递引用，不复制不可追踪的自由文本事实。

#### Tool call/result

```text
tool_call: id, tool_id, version, task_id, node_id,
           arguments, permission_scope, timeout_ms, idempotency_key
tool_result: call_id, status, data_refs[], evidence_ids[],
             started_at, finished_at, error {type, retryable, detail}, metrics
```

工具状态统一为 `success / partial / failed / skipped / cancelled`；工具不能用空数组表示失败。

#### Document/chunk

```text
document: id, source_id, canonical_url, title, publisher,
          published_at, collected_at, content_hash, mime_type, version
chunk: id, document_id, ordinal, text,
       section_path, char_start, char_end, token_count,
       content_hash, embedding_version
```

引用至少定位到 `document_id + chunk_id + 字符区间`，同时保留原始快照哈希。

#### Memory item

```text
id, memory_type, scope_id, content,
source_refs[], created_by, verified_by,
created_at, expires_at, superseded_by, status
```

只有带来源的事实和用户明确偏好才能进入长期记忆；模型推测、未确认关系和隐藏推理不得写入。

## 4. 本轮最小闭环：P0 SBOM/资产仿真与可审计任务工作台

本轮目标不是一次完成全部 Agent 能力，而是形成一个真实、可复核的闭环：

> 用户导入或生成明确标注的资产清单 → 系统将组件/版本映射为研判对象 → 用户发起 AI 安全任务 → 系统固定上下文 → 生成受限计划 → 调用真实采集/本地工具 → 展示角色与工具轨迹 → 形成有证据的资产影响与处置结果 → 保存运行 → 质量页如实显示已测与未测。

### 4.1 本轮应落地的最小范围

1. **SBOM/资产仿真输入闭环**
   - 本轮以现有资产对象作为统一中间格式，接受已专项测试的 CycloneDX JSON 1.3–1.7；只承诺当前解析并保存的组件身份、版本、PURL/CPE、生成工具和快照字段。
   - 导入结果展示原始条目数、成功映射数、缺少版本数、无法识别组件数和重复合并数。
   - 组件保留生态、包名、版本以及可选 PURL/CPE 来源；无法可靠映射时进入“待确认”，不做模糊命中。
   - 仿真资产必须带 `is_demo=true` 和仿真场景说明，不与真实资产混称。
   - 用至少三种仿真场景贯穿闭环：明确受影响、明确不受影响、版本或条件未知。
   - 事件匹配后生成四档结论、证据 ID、理由、优先级和修复建议；用户可从资产回到事件与来源。

2. **统一任务入口**

1. **统一任务入口**
   - 工作台以任务输入为主入口。
   - 输入包含问题、资产范围、来源范围、时间窗口、补证上限和模型开关。
   - 提交前展示范围摘要。

3. **上下文快照**
   - 任务开始时记录事件、资产、文档/证据和历史轮次引用。
   - 回答展示当前上下文对象。
   - 本轮可先把快照保存在运行详情中，不必立即建设独立长期记忆库。

4. **线性 DAG 兼容层**
   - 将现有采集、整理、富化、研判、回答映射为带依赖的节点列表。
   - 每个节点显示角色、输入、产出、工具、状态、耗时与停止原因。
   - 本轮允许 DAG 是线性的，但数据结构必须保留 `depends_on` 和成功判据，为后续并行与重规划留接口。

5. **角色交接记录**
   - 在现有角色轨迹上增加结构化“产出引用、遗留问题、接受/驳回”。
   - 至少覆盖 Planner → Retriever → Evidence Auditor → Assessor/Writer。
   - 明确这些是同一进程内的职责分工。

6. **统一工具卡**
   - 现有采集和补证工具统一显示工具 ID、调用原因、输入摘要、结果、证据 ID、耗时和错误。
   - 固定白名单与调用预算不变。

7. **知识可视化最小版**
   - 事件详情展示来源证据、资产判断和已有关系。
   - 用列表/简图表达“来源 → 事件 → 资产 → 处置”，每条边绑定证据。
   - 不在本轮声称全文 RAG 或多跳推理。

8. **真实采集证据**
   - 继续用真实登记来源采集，不补写历史数据。
   - 展示逐来源成功、失败、跳过、发布到发现延迟和快照位置。
   - 保留连续运行天数和 `complete_days` 证据。

9. **诚实质量面板**
   - 将 30 条规则回归与 4 条 QA 标注集拆开显示。
   - 展示真实分母、合成比例、执行时间和局限。
   - 跨文档、多跳、个性化、富化准确率/召回率尚未专项评测时标“未评测”。

### 4.2 P0 验收门

- [x] 一份 Syft 生成的 CycloneDX 资产清单可完成导入、映射、研判、处置输出与证据回溯。
- [x] 仿真资产显著标识；SBOM 未声明的部署上下文保持未知并进入假设说明。
- [ ] 受影响、不受影响、待确认三类仿真场景均有可复核结果，不把未知判为安全。当前标准样例已覆盖“不受影响”和“待确认”。
- [ ] 一次任务可从输入连续完成到运行记录，不依赖多个孤立页面手工拼接。
- [ ] 任务保存范围、约束、上下文对象和运行 ID。
- [ ] 所有步骤有状态、角色、输入、产出、耗时和停止原因。
- [ ] 所有外部调用来自工具白名单，错误不冒充空成功。
- [ ] 每条事实结论能回到证据 ID；缺证据时拒答或待确认。
- [ ] 用户中断后已完成节点和证据仍可复核，未完成节点不标成功。
- [ ] 真实采集不写入伪造历史，逐来源结果与快照可核对。
- [x] 赛题指标严格区分实测、未知和规划。
- [x] 现有安全、数据契约和核心回归测试保持通过（203 项）。

### 4.3 P0 不得提前宣称

- 完整支持 SPDX、CycloneDX 或其他标准，除非对应解析、字段映射与错误用例已通过专项测试。
- 对公网或生产环境完成真实资产发现；本轮是授权资产输入与仿真闭环。
- 全文或向量 RAG。
- 复杂多轮上下文管理。
- 跨文档综合推理或多跳推理。
- 多 Agent 独立协作。
- 长期记忆或自动学习。
- 个性化推荐。
- 完整自愈。

## 5. P1：全文知识库与可复核 RAG

### 5.1 建设内容

- 为 HTML、JSON、XML、PDF 和纯文本建立统一文档解析管线。
- 保存规范化全文，原始快照继续不可变留存。
- 按标题层级和语义边界分块，记录字符区间、块哈希和解析器版本。
- 建立关键词索引；向量索引作为可替换检索器，不成为唯一通道。
- 检索流程采用候选召回 → 去重 → 重排 → 上下文组装。
- 回答引用精确到文档块和原文区间。
- 文档更新时按内容哈希版本化，旧任务继续引用旧版本。

### 5.2 分块策略

- 优先按文档结构切分：标题、段落、列表、表格行。
- 目标块大小和重叠由离线检索实验选择，不在设计阶段写死最佳值。
- 表格、版本区间、CVSS 向量和代码块保持语义完整。
- 每个块继承文档元数据与章节路径。
- 禁止把不同来源拼成一个不可追踪块。

### 5.3 P1 验收门

- [ ] 任一答案引用可定位到原始文档、块、字符区间和快照哈希。
- [ ] 文档更新后旧引用仍可重放。
- [ ] 至少 100 条冻结检索题完成关键词、混合检索与重排对照。
- [ ] 报告 Recall@k、MRR、nDCG、无答案误召回率及真实/合成分组。
- [ ] 删除或替换关键证据块后，答案与引用按预期变化。
- [ ] 检索失败时拒答，不用模型记忆补写。

## 6. P2：多轮上下文与分层记忆

### 6.1 上下文管理

- 每轮保存用户目标、显式选择、解析实体、继承约束和上下文快照。
- 指代解析必须输出所指对象和置信度；多候选时请求确认。
- 话题切换创建新焦点，不让旧事件污染新问题。
- 会话摘要只压缩已确认事实，并保留回到原始轮次的引用。
- 上下文达到预算时优先保留任务目标、用户约束和证据引用。

### 6.2 记忆分层

| 记忆 | 生命周期 | 可写内容 | 写入条件 |
| --- | --- | --- | --- |
| 工作记忆 | 单次节点/任务 | 当前候选、临时计划、工具结果 | 自动，任务结束可清理 |
| 会话记忆 | 一个线程 | 已确认焦点、用户选择、未解决问题 | 结构化验证后写入 |
| 知识记忆 | 跨任务 | 有来源事实、审核通过的关系、组织策略 | 来源+审核+版本化 |
| 用户/组织偏好 | 跨任务 | 明确提供的维护窗口、风险策略 | 用户授权，可查看和删除 |

模型生成的摘要不能成为新事实来源。事件撤回、资产更新或文档新版本应触发记忆失效或替代关系。

### 6.3 P2 验收门

- [ ] 30 组、每组 3-6 轮的冻结多轮集覆盖回指、条件继承、修改、对比、切换和拒答。
- [ ] 报告逐轮正确率、整段全对率、上下文继承错误率和历史污染率。
- [ ] 用户可以查看、修正、删除长期偏好。
- [ ] 被撤回或过期事实不会继续作为有效记忆进入回答。
- [ ] 同一任务在固定上下文快照下可重放。

## 7. P3：任务 DAG 与多角色交接

### 7.1 DAG 能力

- Planner 根据任务目标生成白名单动作组成的结构化 DAG。
- Auditor 在执行前检查授权、预算、数据依赖和成功判据。
- Scheduler 只调度依赖已满足的节点，独立只读节点可以并行。
- 工具结果进入节点判定器：成功、部分成功、可重试失败、不可重试失败或需要人工。
- 缺口未减少、来源冲突或工具失败时允许受限重规划。
- 每次修改计划形成新版本，保留差异和原因。

### 7.2 多角色交接

- Planner 交付目标、DAG 和成功判据。
- Retriever 交付文档/块/关系引用和检索局限。
- Analyst 交付候选结论与所需证据映射。
- Assessor 交付资产影响、规则理由和证据。
- Auditor 接受、驳回或要求补证，必须写明原因。
- Writer 只组织审核通过的结论，不新增事实。

“多角色”只有在交接对象、独立接受/驳回和运行证据存在时才成立；“多 Agent”还要求执行单元具有独立状态和消息协议。

### 7.3 P3 验收门

- [ ] DAG 可表达串行、并行、条件分支、人工等待和取消。
- [ ] 任一节点可从 checkpoint 恢复，不重复产生不可幂等副作用。
- [ ] Auditor 能在自动化测试中否决无证据结论。
- [ ] 故障后重规划不超过预算和白名单。
- [ ] 对照固定流水线、单 Agent 编排、多角色审核编排，报告成功率、证据完整率、错误结论率、调用数、耗时和成本。
- [ ] 完成移除 Planner、Auditor、预算和停止策略的消融实验。

## 8. P4：跨文档、多跳与策略感知建议

### 8.1 建设内容

- 从文档块中抽取实体与关系，所有边绑定块级证据。
- 建立文档 A → 实体/事件 → 文档 B → 资产/处置的受限路径查询。
- 冲突关系并存，审核后才生成有效关系。
- 回答输出结构化理由图：结论、事实节点、关系边、规则和证据。
- 引入组织策略输入：维护窗口、业务关键性、禁止动作、负责人和可接受停机。
- 处置建议按策略排序，并解释排序因子；不从用户隐式行为推测偏好。

### 8.2 P4 验收门

- [ ] 两文档、两跳、三跳题集分别有独立来源和路径金标准。
- [ ] 报告文档召回率、路径精确率/召回率、最终答案准确率和证据完整率。
- [ ] 多跳答案的每条边可打开原文证据。
- [ ] 冲突来源题不会被静默合并。
- [ ] 策略建议使用专家标注集报告 Top-1/Top-3、NDCG 和不可执行建议率。
- [ ] 在达到上述门槛前，UI 不显示“多跳推理”或“个性化推荐已实现”。

## 9. P5：自动化、自愈与工程化

### 9.1 建设内容

- 外部调度器记录触发来源、计划时间、实际时间和任务 ID。
- 统一故障分类：超时、限流、鉴权、格式变化、上游不可用、数据校验失败。
- 工具声明重试能力、退避策略、备用来源和幂等性。
- 自愈策略只执行预先批准的重试、降级、备用来源和 checkpoint 恢复。
- 无法恢复时转人工，并保留失败上下文。
- 监控采集成功率、延迟、积压、工具失败率、恢复率和连续运行天数。

### 9.2 P5 验收门

- [ ] 通过故障注入验证每类异常的检测、重试、降级和转人工。
- [ ] 自愈成功率有明确分母，人工重跑不计为自愈。
- [ ] 自动触发和人工触发可区分。
- [ ] 连续运行证据覆盖赛题要求的实际观察窗口。
- [ ] 恢复后不产生重复事件、重复快照引用或错误游标推进。
- [ ] 未恢复故障不被“部分成功”掩盖。

## 10. 评测体系

### 10.1 数据集分层

| 数据集 | 用途 | 要求 |
| --- | --- | --- |
| 单元/合成回归 | 防止已知逻辑退化 | 明确 synthetic，不计比赛成绩 |
| 真实核验开发集 | 调试检索、富化和问答 | 来源可复核，允许开发使用 |
| 冻结验证集 | 选择参数和比较架构 | 冻结后不得按题修改逻辑 |
| 第三方盲测集 | 最终能力声明 | 独立标注，开发者不可见答案 |
| 故障注入集 | 自动化与自愈 | 可重复模拟失败并记录期望恢复 |

### 10.2 指标矩阵

- 监测：有效来源类别、成功率、重复率、发布到发现延迟及 `≤24/12/6h` 比例。
- 富化：各维度覆盖、关系准确率、召回率、冲突保留率、错误关联率。
- RAG：Recall@k、MRR、nDCG、重排增益、引用定位正确率。
- 问答：答案准确率、引用支持率、拒答准确率、完整响应时间、P50/P95。
- 多轮：逐轮准确率、整段全对率、上下文污染率、纠错成功率。
- 多跳：路径准确率/召回率、答案准确率、证据完整率，按跳数分层。
- Agent：任务成功率、计划有效率、审核驳回正确率、重规划成功率、工具调用与成本。
- 自愈：异常检测率、自动恢复率、平均恢复时间、错误恢复率。

每个指标保存定义、分子、分母、样本来源、执行版本、时间和局限。任何空样本返回 `null/未评测`。

## 11. 真实采集与赛题指标路线

### 11.1 七天连续运行证据

- 每个自然日必须存在至少一次真实 `collect` 运行记录，才能计入 `complete_days`。
- 7 天证据窗口展示日期、运行 ID、来源集合、开始/结束时间、总体状态、逐来源状态和证据文件位置。
- 部分成功可以保留，但必须展开失败、跳过和未产生数据的来源；不能用总体成功掩盖来源失败。
- 7 天必须由实际日历时间积累，不创建、复制或回填历史运行。
- `complete_days < 7` 时显示“证据积累中（x/7）”，不得称“已完成 7 天稳定性验证”。
- 达到 7 天只证明连续执行，不自动证明全部来源稳定；还要报告成功率和失败记录。

### 11.2 六小时时效证据

- 继续每日真实采集并保留证据文件，不补写历史。
- 以首次发现时间减来源发布时间计算延迟。
- 单独统计不可计算样本，不能用采集时间补发布时间。
- 同时报告 `≤24h / ≤12h / ≤6h` 的事件数、比例和可计算分母。
- `≤6h` 是单事件分档和聚合目标；只有发布时间、首次发现时间都有效的样本进入分母。
- 达到 7 天观察窗口后再报告 7 天聚合结果；观察期内只显示“当前观测”，不称最终成绩。
- 若采集调度间隔本身超过 6 小时，架构上不能支撑 `≤6h` 稳定目标，应先调整调度并重新积累证据。
- 达标声明必须同时给出样本量、未知数、P50/P95 或最大延迟、失败运行和证据文件。

### 11.3 富化准确率与召回率

- 先定义可判定的富化关系：论文关联、版本范围、修复版本、POC 状态、CVSS、资产影响和证据关系。
- 对每类分别建立正例、负例与未知，微平均和宏平均同时报告。
- 当前“维度是否有值”是覆盖率，不是准确率或召回率。

### 11.4 问答准确率与响应时间

- 主口径使用完整响应时间，同时记录首字时间。
- 题集覆盖基础、语义、多轮、跨文档、多跳和拒答。
- 超时和错误进入准确率与时延统计，不从分母剔除。
- `≤5s` 只在固定环境、公开样本量和完整回答口径下判断。

### 11.5 Agent 与自动化

- Agent 等级用行为证据展示：计划版本、工具选择、交接、审核、重规划和恢复。
- 角色数量、工具调用次数不是创新或自主性的成绩。
- “全自动”“自愈”“多 Agent”只有通过专项故障与对照实验后才能标完成。

## 12. 阶段发布规则

每个阶段发布时必须提供：

1. 数据契约版本和迁移说明。
2. 已实现能力与尚未实现能力清单。
3. 自动化测试和固定评测结果。
4. 真实运行证据与失败记录。
5. UI 中实测、未知、规划的对应状态。
6. 回退与数据兼容方案。

只有上一阶段验收门通过，下一阶段能力才可以进入主演示路径。未通过的能力可以以“规划”展示，但不得使用完成态标签或赛题达标表述。

## 13. 推荐实施顺序

1. **本轮 P0**：SBOM/资产仿真输入闭环、统一任务工作台、上下文快照、线性 DAG、角色交接、工具卡、真实采集证据、诚实质量面板。
2. **P1**：全文保存、结构化分块、混合检索和块级引用。
3. **P2**：多轮上下文、会话记忆、知识记忆及失效机制。
4. **P3**：可恢复任务 DAG、受限重规划、多角色审核和架构对照实验。
5. **P4**：跨文档关系、多跳评测和策略感知处置建议。
6. **P5**：自动调度、故障注入、自愈和工程化连续运行。

这一路线优先建立可复核的数据和评测基础，再提高自主性。否则更复杂的 Agent 只会扩大无法测量的行为范围。

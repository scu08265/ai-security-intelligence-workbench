## 3. 为什么还有 4 天缺口

`NumberOfMissedRuns` 与库里的记录一致指向同一个原因：**机器休眠/关机期间计划任务不会补触发**。

- 10-14 04:46Z 之后到 09:45Z 之间空档约 5 小时（本机 12:46–17:45 无运行）；
- 10-14 14:46Z 之后到 10-15 01:46Z 之间空档约 11 小时（本机 22:46–09:46 无运行）。

这两段正好是午饭后的休眠与整夜关机。**计划任务本身没有失效**——恢复供电/唤醒后立刻按小时续上。
因此"连续 7 天"这件事现在只取决于**机器是否每天至少开一次**，不取决于任务配置。

## 4. target_met 何时回来

7 天窗口要求的是"**窗口内每个自然日都有计划运行**"。窗口是滑动的，所以：

```
最后一个缺口 = 2026-10-13
→ 最早可由 2026-10-14 起连续 7 天成立
→ 预计 target_met = true 的日期：2026-10-20（UTC）
```

这是**下界**：任何一天整日不开机，就顺延一天。缺口不会被回填，也不应该被回填。

## 5. 复跑命令

```powershell
.\.venv\Scripts\python.exe tools\check_continuous_run.py --days 7
```

输出 `reports/continuous-run-check.json`，内含逐日计划运行次数、运行 ID、库哈希与预计达成日期。
只想看当天有没有触发时，直接看该文件的 `window.days` 最后一行，**不要只看计划任务的
Next Run Time**——Next Run Time 只说明"下次打算跑"，不等于"上次真的跑了"。

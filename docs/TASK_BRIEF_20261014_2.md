## 一、大方向上还差什么（按对分数的影响排序）

当前活动批次（20261002）的人工核验结果是：答案 correct 5 / incorrect 7 / **partial 26** / undecided 12；
引用 supported 3 / **partially_supported 27** / unsupported 6。按各自的分母口径，答案 13.16%、引用 8.33%。

而决赛"问答质量"10 分的档位是：准确率 ≥75% 合格（6 分）、≥90% 良好（8 分）、≥95% 优秀（10 分）。
**13% 连合格线都不到**，这项如果不动，是整个项目最贵的一处失分。

关键在于**这不是检索问题**：同一批机器指标是文档命中 0.9722、预期词命中 0.9211——文档找对了，
但答案没有把期望的术语/事实说出来（26 题判"部分正确"），引用的句子也不直接支撑答案（27 题判"部分支持"）。
也就是说问题在**答案组织**与**引用选取**这两层，属可修的工程问题。

### 2. 时效性的档位没定稿，而分列口径其实够"良好"

赛题问的是"**漏洞信息**从发布到系统采集的时间延迟"。按来源分列后，漏洞类中位 **7.34 小时**，
落在赛题"≤12 小时良好（4 分）"档；而 `docs/COMPETITION_RUBRIC_MAPPING.md` 目前仍写"合格（3 分）"。
混合口径 15.58 小时应继续保留在附录 B 备查。**这是一个需要定稿的口径决定，不是技术问题**。

### A1（最高优先）问答质量攻坚：把"部分正确"变成可修的清单

1. 答案确实少了期望术语/事实（答案组织问题）；
2. 答案写对了，但引用指向的句子不支撑它（引用选取问题）；
3. 判定标准本身过严（例如期望"必须同时给出两个术语"）。

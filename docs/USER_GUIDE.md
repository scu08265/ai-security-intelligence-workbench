# AI 安全知识情报系统 · 使用指南

版本：0.1.0

本系统是一个面向 AI 软件供应链的安全风险研判工作台：从固定的公开数据源增量采集漏洞与安全知识，
把风险与受管资产关联起来，说明判断依据，并形成可执行的处置清单。系统在本机保存数据库、原始快照、
研判结果和运行记录；采集器会访问已登记的公开互联网来源。启用云端模型辅助后，候选事件内容和用户问题
会发送给配置的模型服务商，密钥只从本机环境变量读取。不开启模型时，问答使用本地混合检索与证据抽取。

产品主线始终是：**公开披露 → 系统发现 → 证据确认 → 关联资产 → 给出处置 → 留痕验证**。
AI 用于筛选大量候选情报、辅助建立检索关联和解释已有结论；它不能凭常识补写事实，最终结论必须回溯到
来源证据、资产版本和配置条件。

## 一、系统能做什么

| 能力 | 说明 |
| --- | --- |
| 处理过程 | 抓取→整理→补证→判断影响全程逐步展示。每一步都给出"做了什么 / 得到什么 / 产出什么 / 有什么影响"，并附**实测**耗时（不是动画） |
| 流式问答 | 答案按证据逐段实时生成，可选让大模型把已有结论换个说法并逐字输出（模型只能改措辞，不能加事实） |
| 监测采集 | 从后端登记的数据源按窗口增量采集，逐来源如实记录抓取数、保留数、过滤数、耗时与错误 |
| 事件归一 | 把不同来源对同一漏洞的记录归并为一条事件，保留来源间冲突（版本区间、严重度不一致等） |
| 证据富化 | 按六个维度盘点证据完整度（受影响版本、修复方案、严重度、POC、关联关系、官方来源），缺什么就报什么缺口 |
| 资产研判 | 受管资产 × 事件给出 `受影响 / 不受影响 / 待确认 / 不适用` 四档结论，并附判定理由与证据 ID |
| 证据问答 | 基于本地已存证据回答问题，答案、引用、执行轨迹、局限性全部可见；证据不足时明确拒答 |
| 评测回归 | 用小样本金标准案例 + 标注为合成（synthetic）的夹具做本地回归，输出通过率与分类明细 |
| 运行日志 | 采集、富化、研判、问答、评测五类运行记录（按开始时间倒序，默认显示最近 30 条） |
| **AI 参与说明** | 「系统说明 → AI 做了什么」把模型的两处参与点、**提示词原文**、输入输出与限制全部摊开，并明确列出"哪些不是 AI 做的"。提示词由后端读取运行中的代码，不是抄来的副本 |

系统的核心立场是**不编造**：没有采到就显示"尚未采集"；评测没跑就显示"尚未执行评测"、不给任何分数；
来源没给 CVSS 数值就显示"仅有向量，来源未给出数值"而不是 0；POC 未收录时会说明"未收录不等同于不存在"。

## 二、启动

### 1. 安装依赖

```bash
cd competition
pip install -r requirements.txt
```

依赖只有五个包：`fastapi`、`uvicorn`、`httpx`、`packaging`、`pytest`。前端是纯静态页面，
不需要 Node、npm 或任何构建步骤，也不加载任何外部 CDN、字体或图片，完全可离线打开。

### 2. 启动服务

```bash
python -m uvicorn app.api:app --port 8000
```

### 3. 打开控制台

浏览器访问：

```
http://127.0.0.1:8000/
```

服务默认只监听本机回环地址，并且后端会拒绝来自非本机来源的写请求（跨源写入返回 403）。
如需公开部署，必须自行在反向代理层增加身份鉴权。

### 4. 数据位置

数据默认保存在项目下的 `data/`：`intel.sqlite`（事件、资产、研判、运行记录）与 `snapshots/`
（每次采集的原始快照，带 SHA-256）。设置环境变量 `INTEL_DATA_DIR` 可切换目录，
控制台左下角会显示当前实际使用的数据目录，便于确认自己看的是哪份数据。

## 三、推荐演示路径

演示先讲用户需要处理的风险，再展开系统如何得出结论：

**① 风险总览（含「看它怎么工作」）→ ② 初始化核验案例 → ③ 证据问答 → ④ 风险与证据 → ⑤ 资产清单 → ⑥ 处置清单 → ⑦ 系统说明**

左侧导航只有这六项，分两组：「工作台」是日常要用的五页，「系统」是讲清楚这套系统怎么工作的一页。
其余的技术内容（来源明细、处理轨迹、运行记录、评测明细、图例）都收在「系统说明」的五个子标签里，
不再单独占一个导航项。

风险总览默认打开。它先展示今日新增风险、受影响资产、待确认项和立即处置项，并用一条完整故事串联：
系统从公开披露发现风险，确认来源与版本证据，关联演示资产，给出处置动作，最后保留验证记录。

### ① 风险总览 →〔看它怎么工作〕—— 查看系统如何得到结论

默认打开的就是风险总览。点页面上最显眼的 **▶ 看它怎么工作**，进入全流程直播，
下方会按顺序长出每一步的卡片；左上角 **← 返回风险总览** 可以随时退回来。

每张卡片都回答四个问题，颜色区分得很清楚：

| 行 | 含义 | 颜色 |
| --- | --- | --- |
| **做了什么** | 这一步在干什么 | 无标记 |
| **得到什么** | 从外部权威库拿回来的原始内容 | 紫色**虚线** |
| **产出什么** | 系统自己生成的新内容 | 青色**实线** |
| **有什么影响** | 这一步对最终结论意味着什么 | 灰色小字 |

- **卡片是逐步长出来的，不是一次性列出来的。** 每张卡片出现的时刻，就是那一步真的做完的时刻。
- **耗时是实测的。** 卡片右侧的时间由后端用 `time.monotonic()` 量出，跑完显示的是后端给出的总耗时，
  不是界面上的动画。系统做多快就显示多快；某一步只花 0 毫秒，它就显示 `0 ms`。
- 首次演示建议在"抓哪些来源"里选**单个来源**（例如 CISA KEV），把"补证强度"设为**不补证**，几秒就能跑完。
  选"全部登记来源"要 1~2 分钟。

> 选择"全部登记来源"时若未配置 `GITHUB_TOKEN`，`ghsa` 会显示**已跳过**并注明原因 —— 这是如实上报，不是故障。

### ② 初始化核验案例与演示资产

进入「系统说明 → 来源与采集」，点击 **初始化演示数据**。这一步做两件事：

- 载入 `research/cases.json` 里的核验案例（真实公开案例，作为评测金标准）；
- 生成 5 条**合成演示资产**（`is_demo=true`，仅用于演示，不代表任何真实公网资产）。

### ③ 证据问答（流式）

进入「证据问答」面板，用大白话输入问题（例如某 CVE 影响哪些资产）。

- **答案一段一段实时出现**，每一段左侧都标着它引用了哪条证据编号。
- 同时会展示系统的**执行轨迹**：每一步谁在做、做了什么、结果是什么、为什么停。
- 下方还会列出**引用来源**（发布者、可信度、原文摘录）、**每句话对应的证据**、**资产影响判断**、
  以及 **这次回答的局限**（请务必看一眼）。
- 证据不足时系统会**明确拒答**并说明缺什么，不会用模型常识补写答案。

**关于"让大模型换个说法"开关**：默认关闭。打开后，大模型会把已经生成的结论换个更口语的说法，
**逐字实时输出**（文字的右侧会有一个闪烁光标）。这一段用紫色虚线框单独标出，并注明"仅供阅读"。

- 大模型**只能改写措辞，不能新增事实**；它的输出**不进入引用与证据链**。
- 两边说法不一致时，**一律以本地结论为准**。
- 未配置密钥时该开关不可用，界面会直接说明原因，而不是留一个点了没反应的灰框。

> 正文里可能出现 `affected` / `not_affected` 这类英文，那是系统内部的判断代号。
> 答案框上方随时给出中文对照：`affected = 受影响`、`not_affected = 不受影响`、
> `needs_confirmation = 待确认`、`not_applicable = 不在授权范围`。

### ④ 风险与证据

进入「风险与证据」面板，按关键字（CVE 编号、组件名等）检索，点击任意一行查看详情。

**按类型筛选**：下拉框里是四种类型，括号内是当前真实条数（由后端统计，不是写死的）：

| 类型 | 内容 | 来源 |
| --- | --- | --- |
| **漏洞** | CVE 漏洞条目 | NVD / MITRE / OSV / GitHub Advisory / 微软 MSRC / CISA KEV |
| **论文** | AI 安全学术论文 | OpenAlex 学术索引；arXiv（手动选择且网络可用时） |
| **标准与框架** | OWASP GenAI、NIST AI RMF、MITRE ATLAS | 对应官方站点 |
| **政策法规** | 欧盟 AI Act、NIST 新闻 | 对应官方站点 |

> 想找论文就在这里选「论文」。分类由**采集到该条目的来源**决定，不是人工标注的。

条目详情里可以看：

- **受影响版本范围**：逐条标注来自哪个来源（`source_id`）。
- **来源间冲突**：不同来源对版本区间/严重度的不一致会高亮显示，不做静默合并。
- **证据完整度**：六个维度逐一标注"已具备 / 缺失"。
- **证据缺口**：缺失项集中列出，并明确说明"缺失不等于不存在"。
- **流水线轨迹**：每一步的角色、动作、结果与停止原因（含"为什么停在这一步"）。
- **CVSS**：来源只给了向量没给数值时，显示"仅有向量，来源未给出数值"，不会算成 0 分。
- **本事件的影响判断**：该事件下所有资产×事件的判定结果。

如需补齐缺口，可点击 **执行补证调度（最多 10 条）**。

### ⑤ 资产清单

进入「资产清单」面板：查看/新增受管资产。新增表单包含名称、组件、生态、版本、暴露面
（`public/internal/unknown`）、业务重要性（`high/medium/low`）、是否授权采集、触发条件（JSON 对象）。

- 演示资产会带 **合成演示 is_demo** 标记；未授权资产带 **未授权** 标记。
- 真实使用请通过表单录入自己的资产，不要依赖演示数据。

### ⑥ 处置清单

进入「处置清单」面板点击 **重新执行研判**，生成事件 × 资产的四档结论：
`受影响(红) / 不受影响(绿) / 待确认(琥珀) / 不适用(灰)`。

- 每条结论都带**判定理由**列表与证据 ID。设计上，**条件未知、组件不明或事件已撤回都不会被当作"不受影响"**，
  而是落到"待确认"——宁可保守，不做无依据的豁免。
- 未授权资产仍然会被研判并记录为"不适用"，而不是跳过，以便留痕。

### ⑦ 系统说明

导航最后一项。这一页回答四个问题，分五个子标签：

| 子标签 | 回答什么 |
| --- | --- |
| **AI 做了什么** | 全系统只有 2 处用到模型：挑事件、换说法。两处的**提示词原文**逐字贴出（由后端读取运行中的代码，不是抄来的副本）；同时列出"哪些**不是** AI 做的"（采集 / 归一 / 富化 / 研判 / 检索 / 拒答 / 评测） |
| **工具与编排** | 四步流水线、八个角色分别负责什么、什么时候会停下来（最多补 2 轮、最多调 3 次外部接口）、14 个固定来源清单 |
| **来源与采集** | 数据源表（类别、接入方式、是否需 Token、状态、上次成功时间、累计事件数）、勾选与采集、初始化演示数据、逐来源结果（抓取/保留/过滤/新增/更新/耗时/备注与错误/快照哈希） |
| **运行与质量** | 五类运行记录（运行 ID、类型、状态、起止时间、摘要）；以及本地回归评测——未执行时显示"尚未执行评测"且**不展示任何分数**，执行后给出通过率、检索精准率/召回率、问答/引用/拒答准确率与逐题明细；**合成夹具单独标注**（synthetic），并显著展示本次评测的**局限性**条目，请连同分数一起阅读 |
| **状态说明** | 界面上每种颜色、每个徽章、每句提示的含义。这一页是纯静态内容，不调用任何接口 |

> 顶部横幅随时显示当前模式，并常驻一句话说明 AI 到底参与了哪部分。点横幅右侧的
> **AI 做了什么 →** 可直接跳到第一个子标签。

要看事件总数、数据源数、资产数、待复核数、监测覆盖（含后端原文说明
"仅登记而未产生有效数据的端点不计为已接入"）、最近一次采集与评测状态，回到「风险总览」，
展开页面底部的 **高级信息** 即可。

## 四、模型配置（可选）

系统有一个**可选**的大模型辅助路径。配置文件是项目根目录的 `.env`（已被 gitignore，
请勿提交真实密钥）。若该文件**尚不存在**，可从模板复制：

```bash
cp .env.example .env
```

若 `.env` 已存在（例如仓库中已配好），请直接编辑它——不要覆盖，以免丢掉已有密钥。

`.env` 中与模型相关的变量：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 空 | 留空 = 不启用模型（本地证据抽取模式） |
| `INTEL_USE_MODEL` | 开（`1`） | 设为 `0/false/no/off/disabled` 可强制关闭模型，即使有密钥 |
| `INTEL_MODEL_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容端点 |
| `INTEL_MODEL_NAME` | `deepseek-chat` | 模型名 |
| `INTEL_MODEL_TIMEOUT` | `8`（秒） | 单次模型调用超时 |
| `GITHUB_TOKEN` | 空 | 可选。把 GitHub Advisory 的限流从 60/h 提到 5000/h；不配则该来源如实报错，不会以空结果冒充成功 |

密钥只在引擎内部从环境变量读取，**任何接口响应、日志、导出快照里都不会出现密钥**。

### 两种模式的区别

控制台顶部横幅会始终显示当前模式：

- **未配置模型**时显示：
  `本地证据抽取模式：未配置大模型，所有结论完全由本地已存资料拼装`
- **配置了模型**时显示：
  `模型辅助模式：大模型只用来挑事件和换说法，结论仍由本地证据拼装`

配置模型后**变化的部分**：在候选事件已经由采集器取回之后，模型可以参与从候选列表中做挑选/排序，
减少人工翻阅量；「证据问答」页的"让大模型换个说法"开关也会变为可用。

**不变的部分**：采集来源、抓取内容、证据留存、影响研判规则与最终问答结论的**拼装过程完全不受影响**；
所有结论仍然由本地证据拼装，且每条结论都能回溯到证据 ID。系统**从不声称**对大模型的推理过程做过验证。
因此两种模式下的结论口径是一致的，只是人工筛查的工作量不同。

## 五、各面板速查

| 面板 | 主要看什么 |
| --- | --- |
| **风险总览** | 计数瓦片（今日新增风险 / 受影响资产 / 待确认 / 立即处置）、风险故事六步、优先处置表、今日新增待研判；顶部有 **▶ 看它怎么工作** 入口；底部 **高级信息** 折叠区含监测覆盖（`endpoints_with_data` vs `endpoints` 及原文说明）、最近一次采集与评测状态 |

| **资产清单** | 资产列表（名称、组件、版本、暴露面、业务重要性、授权、合成标记）、单条新增表单、生成合成演示资产、删除 |
| **证据问答** | 流式答案（每段标证据编号）、执行轨迹、引用来源、每句话对应的证据、资产影响判断、局限性；可选的大模型转述开关 |
| **系统说明** | 五个子标签：**AI 做了什么**（提示词原文 + 哪些不是 AI 做的）、**工具与编排**（四步 / 八角色 / 停止条件 / 14 个来源）、**来源与采集**、**运行与质量**（运行记录 + 评测）、**状态说明**（颜色与徽章图例）。技术细节都在这一页，不再单独占导航项 |

> 不在导航里但可达的一页：**风险处理过程**（全流程直播），入口是风险总览上的 **▶ 看它怎么工作**，

> 每张含"做了什么 / 得到什么 / 产出什么 / 有什么影响"、实测耗时、涉及的事件与来源 ID，
> 顶部有实时计数与总耗时，底部有本次结果汇总与逐来源表。

### 颜色约定（贯穿全站）

- **青色实线** = 系统自己生成的内容（产出）
- **紫色虚线** = 从外部权威库拿回来的内容（得到）

### 状态色约定

- 研判：`受影响` 红 · `待确认` 琥珀 · `不受影响` 绿 · `不适用` 灰
- 事件：`已确认` / `待复核` / `已撤回`
- 运行：`成功` / `部分成功` / `失败` / `已跳过` / `闲置` / `进行中`
- 编号与哈希一律等宽字体显示，避免误读。

### 界面约定

- 顶部横幅的两种模式文案始终可见，不会因为面板切换而消失。
- 出错时，界面会直接显示后端返回的 `detail` 文案，不做美化掩盖。
- 链接只有在确实是 `http(s)://` 开头时才可点击；否则以纯文本呈现，防止把非 URL 文本当链接。
- 页面宽度窄至约 900px 时布局自动收窄为单列；键盘 Tab 可遍历所有控件，标签页支持方向键/Home/End 切换。
- 已经做完的步骤卡片**不会**残留"进行中"状态：该阶段一有真实结果，占位卡片就会被移除。

## 六、浏览器端自检（可选）

除 Python 测试外，仓库还带一个真实浏览器自检脚本，用来验证只有浏览器里才会暴露的问题：
步骤卡片是否真的**逐步**出现（而不是一次性列出）、流式答案是否真的**逐段**增长、
模型逐字输出是否合并为**一个**段落、有无 JS 报错与失败请求。

Playwright **不是运行本系统的依赖**，只在跑这个脚本时才需要：

```bash
pip install playwright && playwright install chromium

python -m uvicorn app.api:app --port 8020      # 另开一个终端
python tools/browser_check.py --base http://127.0.0.1:8020
```

脚本逐项打印 `[ok]` / `[FAIL]`，退出码 0 表示全部通过，截图落在 `artifacts/browser/`。

> 脚本内部刻意不用 `page.wait_for_function`：页面自己的 CSP（`script-src 'self'`，不含 `unsafe-eval`）
> 会禁止它编译字符串表达式。测试工具被页面的安全策略挡住，本身正说明 CSP 生效了。

## 七、已知边界与不做的事

请务必连同上面的功能一起阅读本节。以下不是"待办事项"，而是这套系统**有意划定的边界**。

1. **演示资产是合成数据。** 点击"生成合成演示资产"或"初始化演示数据"产生的资产
   （`is_demo=true`）是为演示与回归而编造的合成条目，**不代表任何真实公网资产**，
   也不构成对任何实际系统的描述。真实使用请通过资产表单录入自己的资产。

2. **本地评测是小样本、非盲测的回归，不是正式成绩。** 评测用的是本地金标准案例加少量合成夹具
   （`synthetic` 会被单独标注），规模小、题目已知、由本项目自己维护，
   属于"防回归"的自检，**不代表比赛成绩，也不具备任何外部权威性**。
   未执行评测时系统不提供任何分数。

3. **未收录 POC 不等于不存在 POC。** 某个事件没有 POC 记录，只说明已接入的来源在本次窗口内
   没有提供可用的 POC 资料。系统只记录 POC 的存在性与出处，**从不执行任何 POC/EXP 代码**。

4. **未出现在 CISA KEV 中不等于该漏洞未被利用。** CISA KEV 是权威的在野利用情报之一，
   但它的收录有自身口径与滞后性。事件不在 KEV 中，**不能**推断"未被利用"，
   只能说明"本次采集窗口内未见 KEV 收录"。

其他边界：

- **不接受任意 URL。** 前端没有 URL 输入框；采集目标只能是后端注册表中已登记的数据源。
  这样既能避免把采集器变成任意请求代理（SSRF 风险），也让"能采什么"始终可审计。
- **只在本机运行。** 服务默认监听回环地址，写操作拒绝跨源请求；公开部署需自加鉴权。
- **不保证情报实时。** 当前注册的十个来源的"实时"标记均为否，采集是轮询式增量；
  具体到某事件的时效性请以快照哈希与采集时间为准。
- **不做漏洞利用、不做扫描、不做攻击性动作。** 系统只做采集、归一、富化、研判、
  证据问答与自评测，不会对任何目标发起探测或利用。
- **部分成功就是部分成功。** 来源被限流、超时、缺 Token 时，结果里会如实标记
  `partial` / `failed` / `skipped` 并给出错误原文，不会用静默的空结果伪装成"采到 0 条"。
- **答案可能拒答。** 本地证据不足时，问答会给出拒答与缺失项说明，这是设计预期，不是故障。

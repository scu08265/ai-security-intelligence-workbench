# B 任务二：争议题专项报告（评价口径、证据缺口与可选判定）

本报告只处理**需要人决定的口径与证据缺口**，并给出有依据的统一口径提案。
按提案口径得出的结论仍然只是 **B 类机器辅助建议**，不是人工金标准（C 类当前 0 条）。

数据来源：`artifacts/b_eval/qa_machine_adjudication.json`、`qa_gold_evidence_packet.md`、
`qa_candidate_answers.json`、`refusal_failure_classification.json`、`docs/B_REFUSAL_RULES.md`、
`formal_qa_results.json`（全部为本地实测产物）。

---

## 争议 1：跨文档「是否算综合」（BQA-031～038，8 条）

**事实（实测）**：8 题全部作答，引用覆盖 1～2 个 `document_key`（如 BQA-031 引用
`paper:2609.29429` 与 `paper:2609.28915`），答案正文由引用原文拼接而成；
`qa_machine_adjudication.json` 中 8 条的 `cross_document.synthesis_proven = false`。

**口径提案**：只有当答案显式整合两个及以上来源（跨来源比较、合并、或对每个来源分别给出
可归属结论并共同支撑答案）时，才判 `correct`；仅并列引用多来源摘录时，**答案正确性最多判 `partial`**。

**依据**：① 项目既有结论「检索到多个文档 ≠ 完成跨文档推理」；② 自动规则 `R-QA-QUOTE`
只证明"答案是引用拼接"，不证明"结论来自多来源整合"；③ 8 条答案中未出现跨来源比较措辞。

**按提案口径的机器建议**：8 条 `答案正确性 = partial（pending_human_review）`、
`引用支持性 = partially_supported`。

**可选判定与后果**：

| 选项 | 后果 |
| --- | --- |
| 采纳提案（并列引用判 partial） | 8 条进入答案准确率分母且计为"不完全正确"；引用准确率分母含 8 条 partial |
| 认为并列引用已足够 → 判 correct | 需要为"多来源引用即可"另立判据，并与既有结论冲突，需一并改口径说明 |
| 认为无法判定 → unknown | 8 条单列，不进任何分母 |

## 争议 2：单通用词查询是否应拒答（BQA-046 `vulnerability`、BQA-050 `security`）

**事实（实测）**：两题均被判 `should_refuse=true` 但系统作答；系统在**事件索引**里
分别命中 5 个标题含该词的事件，返回真实事件摘要（BQA-046 返回多条 CVE 描述，
BQA-050 返回 OWASP 页面开头）。`refusal_failure_classification.json` 将其单列分类
`generic_word_answered_from_event_index`，并注明"属对 should_refuse 的定义分歧"。

**口径提案**：若查询仅由单个通用安全词构成、且系统无法将该词收敛到**同一实体/对象**，
则返回多条不相关事件不构成对该问题的回答 → 维持 `should_refuse=true`，
系统行为判 **`拒答正确性 = incorrect`**（漏拒答）。

**依据**：① 评测集原意（这两题放在"拒答及证据不足"类别）；② `B_REFUSAL_RULES.md` R4
「仅有通用词命中不等于充分证据」；③ 返回内容彼此无共同主体。

**可选判定与后果**：

| 选项 | 后果 |
| --- | --- |
| 维持应拒答 → 系统 incorrect | 拒答召回率分母 12，漏拒答 +2 |
| 改为应作答 → 需改题目期望 | 属于**评测集变更**，必须同时重新定义"通用词可接受证据"的判据；本轮不建议 |
| 判 unknown | 2 条单列，不进拒答分母，但需在报告中说明口径未定 |

## 争议 3：多轮追问的期望与证据使用（BQA-025～030，6 条）

**事实（实测）**：5 题系统拒答（025/026/028/029/030），只读探测显示**预期文档在库**
（各 1 个）且预期词命中 24～229 个分块；BQA-027 作答但无引用。
`B_REFUSAL_RULES.md` R5 记录"RAG 侧当前不继承会话上下文"。

**口径提案**：多轮题的期望仍为**应作答**（题目本身给出了上下文），系统未使用已存在的证据
即判 **`答案正确性 = incorrect`**；这属功能缺口而非评测数据缺口。

**可选判定与后果**：

| 选项 | 后果 |
| --- | --- |
| 采纳提案 | 5 条进入答案准确率分母并计为错误；同时记为"多轮能力未实现" |
| 认为多轮期望未定义 → unknown | 5 条单列；但会掩盖已实测的"证据在库未被使用"事实 |

## 争议 4：多跳推理的证据路径（BQA-039、BQA-040，2 条）

**事实（实测）**：两题期望拒答，系统作答；答案来自事件索引，引用来自论文正文/参考文献段落，
**无实体—关系—客体路径**；离线路径器 `tools/multihop_path_retriever.py` 显示
`cross_document` 路径 0/21（缺 `term_node_with_evidence` 21 次、`document_to_document` 126 次）。

**口径提案**：缺少可复现关系路径时不得给出多跳结论 → 判 `拒答正确性 = incorrect`
（违反 R4），并在能力分析中标记"多跳未实现"。

**可选判定与后果**：

| 选项 | 后果 |
| --- | --- |
| 采纳提案 | 拒答召回率分母含 2 条漏拒答；同时作为多跳能力缺口证据 |
| 判 unknown | 需先定义"多跳可接受证据"判据，否则该维度无法评测 |

## 争议 5：引用"可追溯"是否等于"支持"（BQA-009、013、018、022、024，5 条）

**事实（实测）**：5 题引用 ID 全部可在库中取回（全局可追溯率 187/187 = 100%），
但答案正文不是引用原文的逐字拼接（自动规则 `R-QA-QUOTE` 不适用），
因此无法用文本层规则判断引用是否支持结论。

**口径提案**：把"引用可追溯"与"引用支持结论"分列两个指标；
文本层不可判定的题按 `引用支持性 = unknown`，需人工阅读引用段落与答案结论后判定。

**可选判定与后果**：

| 选项 | 后果 |
| --- | --- |
| 人工判定 supported/partially_supported/unsupported | 5 条进入引用准确率分母 |
| 判 unknown | 5 条单列；引用准确率分母相应减少（需在报告中说明） |

## 4. 发现的缺陷与限制

### 4.1 【缺陷 D-1，高】52.4% 的分块被问答链路静默丢弃 —— 需要修改共享模块

**现象**：`app/rag.py::chunks_from_records` 转换语料时，3639 个分块只有 **1733 个通过校验**，
**1906 个（52.4%）被静默丢弃**。

**根因（已定位并实测）**：

```python
# app/rag.py::chunks_from_records
body = _text(item.get("text") or item.get("quote"))   # _text() 会 .strip()
...
if start < 0 or end != start + len(body):             # 用 strip 之后的长度去校验区间
    continue                                          # 静默丢弃，无任何日志
```

`_text()` 做了 `.strip()`，而随后的区间校验用的是**去空白后的长度**。任何以换行或空白结尾的
分块都会因为 `char_end != char_start + len(stripped)` 被判定为"区间不一致"而丢弃。

**实测证据**：

- 数据库层面 **3639/3639** 个分块的 `char_end - char_start == len(原始 text)` **完全一致**，
  即**落库数据没有问题**，问题只在校验逻辑。
- 被丢弃的 1906 个分块全部因"首尾空白"触发，样例：区间 1295..2291、原始长度 996、
  strip 后 995，正文以 `...lation.\n` 结尾。
- 逐文档可见率差异很大：`nist_news`/`owasp_genai`/`nist_ai_rmf`/`mitre_atlas` 为 100%，
  但 16 篇 arXiv 论文只有 **28.4%–47.5%**，`eu_ai_act` 为 49.5%。

**影响**：问答链路的 RAG 检索实际只能看到不到一半的语料，且丢失是**系统性**的（偏向行尾对齐的分块）。
这也是第 4 节若干问题检索不到文档的直接原因之一。

**修复位置属于共享问答链路**（`app/rag.py`，或 `app/rag_corpus.list_chunk_records` 输出已规范化文本），
**本阶段未做任何修改**，需你单独批准。

### 4.2 【缺陷 D-2，中】单英文专名 + 中文疑问句会得到 0 命中

**位置**：`app/rag.py::retrieve_chunks`

```python
if not exact_identifier and len(unique_query) >= 4 and len(matched) < 2:
    continue
```

**实测**：

| 查询 | 词元 | 命中 |
| --- | --- | --- |
| `DistillGuard` | `[distillguard]` | 77 条（检索层正常） |
| `DistillGuard 是做什么的？` | `[distillguard, 是做, 做什, 什么, 么的]` | **0 条** |
| `OllamaDrama 蜜罐观察到了什么？` | `[ollamadrama, 蜜罐, …]` | **0 条** |
| `哪些文档讨论了 AUROC？` | `[auroc, 哪些, 些文, …]` | **0 条** |
| `欧盟 AI 法案对透明度有什么要求？` | `[ai, 欧盟, 法案, …]` | **0 条** |

**根因**：中文问句被切成大量不匹配英文语料的二字词元，使 `len(unique_query) ≥ 4` 成立，
而实际只匹配到 1 个有效英文词元 → 被守卫丢弃。`app/rag.py::terms()` 的中英扩展表只有 7 条
（提示词注入 / 远程代码执行 / 拒绝服务 / 修复 / 缓解 / 漏洞 / 供应链），覆盖不了常见问法。

### 4.3 【限制 D-3，中】问答层从不返回多文档引用

13 条用例中，**`distinct_docs` 始终 ≤ 1**——即便问题是明确的跨文档问题
（"NIST AI RMF 和欧盟 AI 法案分别要求什么"）。

**原因（代码）**：`answer_with_rag(..., max_chunks=6)` → `retrieve_chunks(..., limit=12)`
→ `assemble_context(max_chunks=6)`，只保留得分最高的 6 个分块，通常全部来自同一文档。

**结论**：**现有问答链路不具备跨文档综合能力**。检索层能返回多文档（见
`B_RAG_RETRIEVAL_EVAL.md` 第 3 节），但问答层不会把它们组合成结论。**不得声称已完成跨文档推理。**

### 4.4 【不一致 D-4，低】答案文案与文档引用互相矛盾

**2 条**用例（`term-prompt-injection`、`cross-doc-3`）返回的 `answer` 是
"现有证据中未找到可匹配的事件，无法可靠回答"，但同一响应里 `document_citations`
却有 5–6 条文档引用。

> **订正（2026-09-30）**：本节初稿写作"3 条用例"，按实测数据应为 **2 条**——
> 只有同时满足"事件路径无证据"且"文档路径有引用"的用例才构成矛盾，
> 其余空事件用例的文档引用数为 0。修复与效果见 `docs/B_RAG_FIX_REPORT.md` 第 4 节。

**原因（代码）**：`intelligence.answer_question` 有两条并行路径——结构化事件路径与 RAG 路径。
当**没有匹配事件**时，事件路径提前返回拒答文案，而 `with_rag()` 仍会把 RAG 结果附加到响应上。
前端读者会看到"无法回答"却同时看到引用。

## 5. 未确认事项

- 引用**是否支持结论**未做人工核验（只验证了引用 ID 可追溯）。
- 13 条问题的预期答案由本任务编写，**未经人工核验**，因此上表不能作为准确率分母。
- `agents.answer` 会在语料库中写入 `runs` 与上下文快照；本阶段在**副本**上执行，
  真实库未受影响，但也因此**未在真实库上验证写入行为**。
- 未测试 `/api/chat` 的 HTTP 层（只测了其直接调用目标 `agents.answer`）。

## 6. 结论

问答链路可以运行、可以返回可追溯的引用、可以在无关问题上正确拒答；
但存在**一个高影响的共享模块缺陷（D-1，52% 语料被丢弃）**，且**不具备跨文档综合能力（D-3）**。
在 D-1 修复之前，任何基于该链路的问答准确率评测都不可信。
